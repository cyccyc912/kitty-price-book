# 喵喵价格本 🎀

> 服装代理的随身报价本 —— 售价、单卖明细、能不能单卖、尺码、标签，掏手机一查就知道。
> 给 iPhone 用的 PWA：加到主屏幕就是一个 App，**不用登录、不联网也能用、数据只存在自己手机里**。

---

## 一、功能一览

| 模块 | 能力 |
| --- | --- |
| 商品录入 / 编辑 | 商品名、货号、图片（拍照或相册）、售价、**多条单卖项**、是否可单卖、尺码、标签、备注 |
| 是否可单卖 | 四选一：**可单卖 / 不可单卖 / 仅整套 / 需询问** |
| 单卖项（重点） | 一件商品可加**最多 6 条**单卖项，每条**自己起名 + 定价**。三件套可以记成「上衣 ¥89、裤子 ¥79、内搭 ¥49」，报价时一眼看清哪个部件卖多少 |
| 单卖价逻辑 | 选「可单卖」时标为"建议填写"，一项没填会提示一次但仍可保存；其余状态可留空 |
| 商品列表 | 卡片显示图片、名称、货号、售价、可单卖状态、尺码、标签、备注；单卖显示**最低价**，如「单卖 ¥49 起 · 3 项可单卖」 |
| 旧数据兼容 | 以前存的单个单卖价，打开后自动变成一条名为「单卖」的项，**数据不丢、界面无感** |
| 筛选 | 全部 / 可单卖 / 不可单卖 / 仅整套 / 需询问，另外可按**标签**、按**尺码**筛选 |
| 搜索 | 商品名、货号、标签、尺码、备注，支持空格分词（如 `夏款 连衣裙`） |
| 排序 | 最新添加、价格从高到低、价格从低到高 |
| 商品详情 | 完整信息 + **单卖逐项明细**（每项可单独复制）+ 单卖合计 + 编辑 + 删除 + 一键复制售价 / 单卖明细 / 全部信息 |
| 设置 | 导出 JSON 备份、导入 JSON 恢复、清空数据（两次确认）、占用空间、备份提醒开关 |
| 图片 | 自动压缩到最长边 800px，另存 240px 缩略图；列表只加载缩略图，省流量省内存 |
| 离线 | Service Worker 缓存整个 App，断网照样打开 |
| 存储 | IndexedDB（商品 + 图片 + 设置）；浏览器禁用 IndexedDB 时自动降级 localStorage |
| 容错 | 表单草稿自动保存（误触返回/切后台不丢）、空状态、加载骨架屏、错误提示、离线提示条 |

**没有的东西**（按需求刻意不做）：登录、账号、云同步、颜色字段、库存字段、任何统计上报、任何第三方请求。

## 三、本地预览

PWA 的 Service Worker 只在 `http://` 或 `https://` 下生效，**直接双击 index.html（file://）无法测试离线能力**，请起一个本地服务器：

```bash
# 任选一种，在项目根目录执行
python -m http.server 8899
npx serve .
php -S 127.0.0.1:8899
```

然后浏览器打开 <http://127.0.0.1:8899/>。
用电脑 Chrome 调试时，按 `F12` → 左上角设备图标 → 选 iPhone 14 Pro，即可看到真实手机布局。

### 如果想换一个地址部署（备选方案）

#### 方式 A：GitHub Pages（当前使用中）

```bash
cd clothing-price-pwa
git init
git add .
git commit -m "喵喵价格本"
git branch -M main
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

然后在 GitHub 网页端：

1. 打开仓库 → **Settings** → 左侧 **Pages**
2. **Source** 选 `Deploy from a branch`
3. **Branch** 选 `main`，目录选 `/ (root)`，点 **Save**
4. 等 1～2 分钟，访问 `https://<你的用户名>.github.io/<仓库名>/`

> 仓库必须是 **Public**（私有仓库的 Pages 需要付费）。本项目不含任何隐私数据，公开也没关系。

> ⚠️ **国内网络提示**：`github.io` 在部分国内网络下会被 DNS 污染或 SNI 阻断，导致手机打不开。
> 如果遇到这种情况，改用下面的 Netlify 或 Cloudflare Pages，国内访问通常更顺畅。

### 方式 B：Netlify（拖拽即可，最快，国内访问通常比 github.io 好）

1. 打开 <https://app.netlify.com/drop>
2. 把整个 `clothing-price-pwa` 文件夹**拖进去**
3. 几秒后得到形如 `https://随机名.netlify.app` 的网址，可点 **Site settings → Change site name** 改成好记的名字

也可以连 GitHub 仓库做自动部署：**Add new site → Import an existing project**，Build command 留空，Publish directory 填 `.`。

### 方式 C：Cloudflare Pages（免费、不限流量）

1. 打开 <https://dash.cloudflare.com/> → 左侧 **Workers & Pages** → **Create** → **Pages** → **Upload assets**
2. 把 `clothing-price-pwa` 文件夹拖进去上传
3. 得到形如 `https://随机名.pages.dev` 的网址

### 方式 D：Vercel

1. 打开 <https://vercel.com/new>，用 GitHub 登录并导入仓库
2. Framework Preset 选 **Other**，Build Command 与 Output Directory 都留空
3. 点 **Deploy**，得到 `https://xxx.vercel.app`

> ⚠️ `vercel.app` 域名在部分国内网络下同样会被污染，国内使用优先选 Netlify 或 Cloudflare Pages。

> 三种方式都会自动提供 HTTPS，而 **HTTPS 是 PWA 的必要条件**（也是剪贴板 API 正常工作的前提）。

## 五、iPhone Safari 添加到主屏幕

1. 用 **Safari** 打开上面拿到的网址（⚠️ 一定要用 Safari，微信内置浏览器、Chrome iOS 都不支持"添加到主屏幕"）
2. 点屏幕底部中间的 **分享按钮**（方框 + 向上箭头）
3. 在弹出的菜单里向下滑，找到 **「添加到主屏幕」**，点它
4. 名称会自动填成「价格本」，点右上角 **「添加」**
5. 回到桌面，就能看到粉色小猫图标了。以后**点图标直接全屏打开**，没有地址栏，和原生 App 一样

**几个 iPhone 上的小提醒：**

- 图标名字想改：第 4 步里直接改输入框即可（也可以在 `index.html` 的 `apple-mobile-web-app-title` 里改默认值）
- 第一次打开请**联网一次**，让 Service Worker 把离线资源缓存好，之后断网也能用
- 建议在 **设置 → 显示与亮度** 里关掉"自动锁定"以外的省电限制？不需要，本项目不跑后台任务
- ⚠️ **不要用 Safari 的「无痕浏览」**，也不要"清除历史记录与网站数据"，否则本地数据会被一起清掉
- 数据存在这台手机的这个浏览器里，**换手机 / 换浏览器不会自动同步**，务必用下面的备份功能

## 六、导出备份与恢复数据

### 导出（建议每周一次）

1. 底部导航点 **设置**
2. 点 **导出 JSON 备份**
3. 选择：
   - **含图片**：文件大一些（每张图约 100KB），换手机能完整恢复，**推荐**
   - **仅文字**：文件很小，恢复后图片需要重新拍
4. Safari 会弹出下载，选 **存储到「文件」**
   - 建议存到 **iCloud 云盘**，这样换手机也能拿到
   - 也可以顺手发到微信「文件传输助手」或自己的收藏里

文件名形如 `kitty-price-backup-20261014-1656-full.json`，带日期时间，可以留好几份历史备份。

### 恢复

1. 设置页点 **导入 JSON 恢复**
2. 在文件选择器里找到之前那份 `.json`（在「文件」App → iCloud 云盘 / 最近项目里找）
3. 弹出确认框，选择导入方式：
   - **合并追加**：保留手机上现有的商品，同一件（相同 ID）会被备份里的覆盖
   - **覆盖全部**：先清空当前全部数据，再完整还原成备份的样子 —— **换新手机时选这个**
4. 完成后会提示「导入完成，共 N 件商品」

### 清空数据

设置页 → **清空全部数据** → 可以选择「先备份」，确认后还需要**再点一次**「确定清空」。双重确认，防止手滑。

### 备份提醒

- 超过 **7 天**没备份，设置页会出现橙色提示，底部「设置」标签上会有小红点
- 不需要提醒可以在 设置 → 提醒 里关掉

## 七、数据存在哪里？安全吗？

- 商品文字、图片二进制、设置项全部存在 **浏览器本地的 IndexedDB**（数据库名 `kitty_price_book`）
- **不会**发送到任何服务器，代码里没有任何网络请求（唯一的网络行为是加载自己的页面文件）
- 图片上传前会先在本机压缩（最长边 800px，JPEG 质量 0.82），一张照片通常只占 60～150KB
- 正常存几百件商品 + 图片没问题（iPhone 给单个网站的空间通常是几百 MB 起）
- 设置页可以随时看到 **商品数量 / 图片数量 / 占用空间**

## 八、常见问题

**Q：打开是白屏 / 显示"数据打不开了"？**
多半是浏览器禁用了本地存储。请确认：① 用的是 Safari；② 没有开无痕浏览；③ iPhone 设置 → Safari → 没有把「阻止所有 Cookie」打开。

**Q：选照片时提示"这张图片无法识别"？**
iPhone 默认拍的是 HEIC 格式，个别系统版本转码会失败。解决办法：在相册里打开这张照片 → 截图 → 用截图去添加；或者在 设置 → 相机 → 格式 里选「兼容性最佳」。

**Q：添加到主屏幕后没有图标 / 图标是白的？**
确认访问地址是 `https://`（或本地 `http://127.0.0.1`），并且 `icons/apple-touch-icon.png` 能正常打开。iOS 缓存图标比较顽固，删掉主屏幕图标重新添加一次即可。

**Q：更新了代码，手机上还是旧的？**
Service Worker 会缓存旧版本。改完代码后把 `sw.js` 里的 `CACHE_VERSION` 改成新版本号（例如 `kitty-price-book-v1.0.1`），重新部署；手机上把 App 完全关掉再打开，或在 Safari 里下拉刷新两次。

**Q：能多人一起用吗？**
不能，也不需要。数据各存各的手机，互不干扰。要共享就导出 JSON 发给对方导入。

**Q：会不会哪天收费？**
不会。整个项目是纯静态文件，托管在 GitHub Pages / Netlify / Vercel 的免费额度内，没有任何后端和付费服务。

## 十、设计说明

- 配色：樱花粉渐变 + 奶油白，点缀蝴蝶结红；状态色区分明确（可单卖＝粉、不可单卖＝灰、仅整套＝紫、需询问＝琥珀）
- 图标与空状态插画均为本项目**原创绘制**的粉色小猫，只取"可爱猫咪"的通用风格，未使用任何受版权保护的卡通角色素材，可自由使用与修改
- 移动端优先：所有可点区域 ≥ 44px，输入框字号 16px（避免 iOS 自动放大），适配刘海屏安全区，支持深色模式下正常显示
